# Форматы карт планетарных боёв: `.map` и `.cmap`

## Назначение и проверенные образцы

`*.map` — исходный проект старого MapEditor; `*.cmap` — результат компиляции,
который загружает MatrixGame. Оба файла используют `CStorage` (`STRG`, версия 0),
но наборы таблиц и представление данных существенно различаются. Это не
переименование расширения. Исходник `Duel.map` и соответствующий `Duel.cmap`
найдены в `Mods/Reflection/RefMaps/DATA/Maps` установленного SRHD. Ещё один
исходник, `Training.map`, взят из архива старого MapEditor. Оба `.map` имеют
одинаковую схему 13 таблиц, но разные размеры, наборы объектов и стартовых
роботов. У `Duel.cmap` 18 таблиц. `Duel.map` занимает 400014 байт,
`Duel.cmap` — 2500661 байт.

Справка редактора `MEH.chm` подтверждает открытие/сохранение `.map` и два
способа получить `.cmap`: быструю компиляцию для проверки карты и медленную с
оптимизацией текстурных объединений для релиза. Отдельная команда меняет
ресурсы уже собранной карты, если остальная карта не менялась.

Проверены также 190 `.cmap` из PBNewMaps и Reflection: 189 имеют одинаковую
схему 18 таблиц, `Canonade.cmap` дополнительно содержит таблицы `da` и `0`.
Байтовый roundtrip `Duel.map` родным `CStorage` прошёл, SHA-256 исходного и
перезаписанного файлов совпали. Аналогичная проверка `.cmap` описана в
[`../CMap/README.md`](../CMap/README.md). При анализе игровые файлы не менялись.

## Общий бинарный контейнер

Все целые числа little-endian. Заголовок: ASCII `STRG`, затем DWORD версии
(`0`). Далее DWORD числа таблиц. Имя таблицы — UTF-16LE с нулевым символом;
после него DWORD числа столбцов. Для каждого столбца следуют имя UTF-16LE,
DWORD типа, DWORD размера буфера в байтах и байты `CDataBuf`.

Типы по `MatrixLib/Base/include/CStorage.hpp`: `0` = signed int32,
`1` = DWORD, `2` = byte, `3` = float32, `4` = float64, `5` = wchar/UTF-16.
Первые 12 байт `CDataBuf`: DWORD смещения таблицы массивов, DWORD числа
массивов, DWORD размера элемента. Запись таблицы массивов — три DWORD:
смещение данных, фактическое число элементов, выделенное число элементов.
Смещения относительно начала текущего `CDataBuf`; массивы строк содержат
UTF-16LE. Длина массива измеряется *элементами*, не байтами. Для изменений
важно сохранить порядок таблиц и колонок, дополнительные таблицы, значения
`allocated_count`, а также массивы нулевой длины.

## Исходный `.map`: схема `Duel.map`

Числа в таблице ниже — строки `Duel.map`; у массивных `units`/`points` указано
число элементов. Столбцы в каждой таблице образуют параллельные массивы.

| Таблица | Столбцы | Смысл |
| --- | --- | --- |
| `properties` (56) | `Name`, `Value` (UTF-16) | Размер, свет, вода, небо, параметры сторон, счётчики объектов |
| `textures` (5) | `Type` (DWORD), `Name` (UTF-16) | Исходная палитра текстур местности |
| `units` (20306) | `Unit` (DWORD) | Сетка 143 × 142, исходные данные ячеек местности |
| `points` (20592) | `Z` (float) | Высоты вершин сетки 144 × 143 |
| `toptextures` (217) | `Flags`, `X`, `Y`, `Name` | Верхние текстуры, координаты и флаги |
| `surfaces` (325) | `Flags`, `ZvenCnt`, `Color`, `TexK`, `X0/Y0` … `X3/Y3`, `Name` | Четырёхугольные поверхности |
| `effects` (24) | `X`, `Y`, `XF`, `YF`, `Height`, `Name` | Эффекты с положением и именем |
| `lights` (55) | `X`, `Y`, `Height`, `Range`, `Power`, `ColorR/G/B` | Источники света |
| `objtypes` (139) | `Name`, `Data` (UTF-16) | Каталог объектов; `Data` содержит путь `.vo` и параметры модели/теней |
| `objects` (2157) | `Index`, `X`, `Y`, `XF`, `YF`, `Height`, `Angle`, `AngleX`, `AngleY`, `Scale` | Экземпляры объектов; `Index` ссылается на `objtypes` |
| `buildings` (35) | `X`, `Y`, `Side`, `Kind`, `Shadow`, `ShadowSize`, `Angle` | Здания |
| `cannons` (103) | `X`, `Y`, `XF`, `YF`, `Side`, `Kind`, `Shadow`, `ShadowSize`, `Angle`, `Prop`, `AddH` | Пушки |
| `robots` (0) | `X`, `Y`, `XF`, `YF`, `Side`, `Shadow`, `ShadowSize`, `Units`, `Group` | Стартовые роботы; в образце их нет |

`SizeInUnitsX=143`, `SizeInUnitsY=142`; этим точно объясняются длины `units`
и `points`. У `Training.map` размер 128 × 199, 13 стартовых роботов, и те же
соотношения длин сеток. `robots/Units` содержит строки комплектации, например
`1,3,0|3,4,0|2,1,0|2,3,0|2,8,0|4,3,0`. `X/Y` в исходнике измеряются ячейками; `XF/YF` задают дробную
часть положения. Например, эффекты в `.cmap` имеют мировые координаты,
вычисленные из этих полей. Размер клетки в образце — 20 мировых единиц.

## Игровой `.cmap`: схема и потребитель

Загрузку реализует `MatrixGame/src/MatrixMapPrepare.cpp`, прежде всего
`CMatrixMap::PrepareMap` и `ReloadDynamics`. Все 190 проверенных карт
разобраны без ошибок контейнера. Схема таблиц:

| Таблица | Столбцы | Использование |
| --- | --- | --- |
| `strings` | `String` | Пул имён ресурсов, включая текстуры и модели |
| `cannons` | `X`, `Y`, `Angle`, `Kind`, `Side`, `Shadow`, `ShadowSize`, `Prop`, `AddH` | Готовые игровые пушки; часть целых полей сжата до byte |
| `buildings` | `X`, `Y`, `Angle`, `Kind`, `Side`, `Shadow`, `ShadowSize` | Готовые здания |
| `robots` | `X`, `Y`, `Group`, `Units`, `Side`, `Shadow`, `ShadowSize` | Готовые роботы |
| `objects` | `X`, `Y`, `Angle`, `AngleX`, `AngleY`, `Z`, `Scale`, `Type`, `Shadow` | Размещённые модели и данные теней |
| `surfacesM`, `surfaces` | `Data` | Скомпилированные поверхности/геометрия |
| `roads` | `Data` | `CMatrixRoadNetwork`, версия сериализации 27 в проверенных картах |
| `bridges` | `Data` | Предвычисленные мостовые связи |
| `groups` | `Data` | Геометрические группы для отрисовки |
| `texunions` | `Data` | Объединения текстур |
| `points` | `Data` | Сетка `SCompilePoint` по 12 байт на вершину |
| `inshores` | `X`, `Y`, `NX`, `NY` | Береговые линии |
| `move` | `Data` | Словарь `SCompileMoveCell` по 64 байта на шаблон |
| `bottom` | `Data` | Данные дна |
| `bitmaps` | `Bitmap` | Встроенные растровые ресурсы |
| `properties` | `Name`, `Value` | Параметры, читаемые движком |
| `effects` | `X`, `Y`, `Z`, `Type` | Игровые эффекты; тип — индекс каталога |

Геометрия и навигация разобраны подробнее в [`../CMap/README.md`](../CMap/README.md)
и соответствующих структурах `MatrixGame/src/Common.hpp` и
`MatrixGame/src/Logic/MatrixRoadNetwork.cpp`. `Duel.cmap` содержит 36 свойств;
часть свойств `.map` преобразована (например, отдельные цветовые каналы
собраны в `AmbientColor`), часть счётчиков исходника заменена счётчиками
скомпилированных групп. На этой паре `SideResInfo` и порядок некоторых объектов
различаются: файлы нельзя считать эталоном побайтного вывода компилятора из
имеющегося `.map` без проверки их истории.

### Подтверждённая раскладка нескольких игровых массивов

Загрузчик даёт точный порядок полей, который можно использовать для
валидатора без запуска игры:

- `texunions/Data`: массив DWORD длиной `TexUnionDim²` для каждого объединения;
  значение ссылается на массив в `bottom/Data`, отрицательное означает пустую
  ячейку. `bottom/Data` — массивы int32: первый индекс базового изображения в
  `strings`, затем пары «индекс изображения, индекс PNG в `bitmaps/Bitmap`».
- `bitmaps/Bitmap`: каждый массив — готовые байты PNG. Движок передаёт их
  декодеру PNG. Объединения текстур собираются уже при загрузке игры.
- `groups/Data`: каждый массив начинается с `WORD x`, `WORD y`, DWORD числа
  геометрических секций; каждая секция содержит DWORD текстуры, DWORD числа
  байт индексов, затем индексы `WORD`. После секций идут DWORD числа байт
  вершин и вершины `SCompileBottomVert` по 8 байт: `WORD x,y,tx,ty`.
- `surfaces/Data`: каждый массив начинается с int32 индекса строки ресурса,
  int32 индекса поверхности, DWORD цвета, DWORD числа вершин, DWORD размера
  индексного буфера, DWORD числа групп, float32 `DispX/DispY`. Затем идут
  вершины `(x,y,z,color,tu,tv)` по 24 байта, индексы `WORD` и индексы групп
  DWORD. `surfacesM/Data` имеет отдельную раскладку в `CTerSurface::LoadM`.
- `bridges/Data`: каждый массив начинается с `CRect` (четыре int32: left, top,
  right, bottom), затем последовательность высот float32.

Порядок чтения подтверждён `MatrixGame/src/MatrixMapPrepare.cpp`,
`MatrixGame/src/MatrixMapGroup.cpp` и `MatrixGame/src/MatrixTerSurface.cpp`.

## Что нужно редактору

1. Открывать и сохранять `.map` без потери неизвестных полей и порядка данных.
2. Понимать редактируемые слои: рельеф `points/Z`, сетку `units/Unit`,
   текстуры, поверхности, объекты, свет, эффекты и стартовые силы.
3. Просматривать `.cmap` с сохранением всех таблиц, включая нестандартные.
4. Для нового `.cmap` нужен полноценный этап компиляции: объединение текстур,
   сборка групп и геометрии, карты теней, `points`, `move` и `roads`. Прямая
   замена `X/Y` объектов в `.cmap` допустима лишь при доказанной согласованности
   связанных структур.

**Пока не доказано:** смысл битов `units/Unit` и `toptextures/Flags`, точная
раскладка `surfacesM` и всех вариантов отдельных бинарных массивов,
правила сборки из `.map` в `.cmap`, а также обратимость этого шага.
Исходники MapEditor в форке MatrixGame отсутствуют. Бинарный MapEditor со
справкой и `Training.map` сохранён в
`E:/disasm2500_dev/MatrixGame_analysis/MapEditorLegacy`; архив загружен из
`https://spacerangers3.narod.ru/Progs/MapEditorFull.zip` и оставлен вне
игрового каталога. Два образца `.map` подтверждают общую схему, включая
стартовых роботов, но ещё не покрывают все допустимые значения. Для завершения
спецификации нужна проверка компилятора на копиях карты с контролируемыми
изменениями и исходники с водой и различными типами местности.

Справка описывает настройки проходимости моделей `Full`, `Partial`,
`Chassis`, `Geometry`, `Bridge` и сообщает, что пути ИИ и проходимость роботов
рассчитываются автоматически. Это описание поведения редактора, а не
расшифровка битов в `units/Unit`; соответствие нужно проверить на
скомпилированных образцах.
